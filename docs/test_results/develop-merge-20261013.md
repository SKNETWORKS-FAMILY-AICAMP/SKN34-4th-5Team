평가 패키지는 운영 환경에 추가하지 않고 별도 Linux 컨테이너의 두 venv에서 실행했다. 무료 평가 성공은 실제 제공자의 의미 정확도 통과를 뜻하지 않는다. GitHub의 실제 CI·배포 gate와 제공자 품질 A/B는 실행하지 않았다.

실행 준비 과정의 실패도 구분한다. 기존 테스트 DB 때문에 첫 명령이 입력을 요구해 중단됐고, `--keepdb --noinput`으로 재실행했다. 프론트엔드 첫 컨테이너는 node_modules 마운트 위치로 인한 React 모듈 오류가 있었으며, 올바른 위치에서 전체 검사를 다시 실행했다. 초기 타입 검사의 `PageProps` 오류는 빈 `.next` 환경에서 Next 타입 생성 후 해소됐다. 성능 스크립트의 첫 실행은 `PYTHONPATH` 누락으로 API 호출 전에 중단됐으며 `/app` 경로를 지정해 재실행했다. 배포 Nginx 검사의 첫 실행에는 인증서가 없어 시험 인증서를 제공한 뒤 다시 검사했다. 이 준비 실패를 성공 표본으로 계산하지 않았다.

Windows의 `core.symlinks=false` 및 심볼릭 링크 생성 권한 제약으로 평가 데이터의 이전 경로 링크 두 개는 로컬 checkout에서 링크로 작동하지 않는다. 팀의 Git 링크를 보존하고 `git archive`로 Linux 파일시스템에 펼친 소스에서 이전 경로 호환 검사를 통과했다. Windows에서 직접 평가할 때는 새 정식 경로 `backend/llm/v2/evaluation/`를 사용하거나 링크를 지원하는 Linux 환경이 필요하다.
