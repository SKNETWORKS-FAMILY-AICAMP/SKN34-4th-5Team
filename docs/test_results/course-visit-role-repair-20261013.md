# 내부·외부 방문 구분 및 식당 교체 복구

## 원인

공개 지도는 일반 식당, 구장 내부 먹거리, 술집을 모두 `FOOD`로 표현한다. 기존 편집 대상 선정은 이 공통 분류를 사용했고, 의미 해석 모델에 전달하는 현재 코스에서도 내부 식별 ID·세부 업종이 빠져 있었다. 그 결과 일반 식당을 바꾸려는데 내부 간식 STATION과 술집까지 선택 대상으로 섞였다. 특정 돈카츠 메뉴의 문제가 아니라 **방문 역할이 소실된 문제**다.

별도로 `나머지 일정은 유지해줘` 같은 보존 문구가 기존 단순 교체 문법에 없었다. 주변 검색 결과에 돈까스 전문 업종 매장이 있었어도 원문 검증 경로로 돌아가 추가 메뉴 근거를 확보하지 못하면 전체 교체가 실패했다. 키워드 첫 조회에서 국밥·횟집 등이 반환돼도 다른 표기 조회를 멈추는 문제도 있었다.

실제 저장된 광주 STATION 메뉴는 크림새우·크림닭강정·생맥주이며 돈카츠가 아니다. 기존 선택 연결 시험에 실매장명을 잘못 사용한 fixture는 일반 시험 식당명으로 바꾸고 당시 기록에 한계를 정정했다. 수집 메뉴 데이터 자체는 변경하지 않았다.

## 수정

- `visit_roles`가 서버에서 내부 FOOD/CAFE, 외부 식당/카페, 술집을 구분한다. 수집 장소 ID·출처·세부 업종을 이용하며 특정 매장명을 분기 조건으로 쓰지 않는다.
- 일반 식당·카페 교체의 자동 대상과 확인 선택지에서 내부 매장·술집을 분리한다. 내부 표현 또는 이름·번호·선택 지칭은 명시적 대상으로 취급한다. “구장 간식은 그대로”는 내부 교체 권한으로 해석하지 않는다.
- 의미 해석 입력에 방문 역할과 세부 업종을 제공하고, 수정 적용 직전에도 내부 대상 보호 검사를 한다. 잘못 고른 내부 대상을 유일한 외부 식당으로 바로잡으며, 외부 대상이 없거나 여러 개면 확인을 요청한다. 메뉴 사전 밖 초밥·스테이크에도 적용한다.
- 공개 결과→지도 요청 왕복 후에도 수집 ID와 서버 기억으로 역할을 복원한다. 공개 category 계약은 바꾸지 않았다.
- 돈카츠·돈까스·돈가스와 완전히 해석 가능한 보존 문구를 일관되게 처리한다. 검색어만 맞은 일반 식당을 메뉴 근거로 쓰지 않고 실제 전문 업종·상호를 사용한다. 주차·알레르기 등 추가 조건은 기존 의미 해석·검증으로 보낸다.
- 내부 추천은 기존 자리어때 자료 전용·이번 요청의 내부 표현·요청 종료 후 권한 해제 정책을 유지한다. 내부 매장을 외부 카카오 후보로 다시 수집하지 않는다.

## 고정 입력 평가와 CI

기준 코드는 팀 통합 직후 `6605e8e`다. 기준 기록 후 고정 9개 사례로 초기 메뉴 교체 A/B를 실행했고, 사용자 지적에 따라 내부·외부 경계 8개 사례를 추가하여 같은 17개 입력·정답으로 기준 코드와 최종 후보를 다시 비교했다. 공급자 후보를 고정하고 실제 literal 해석, 후보 선택, 수정 적용 함수를 실행했다. 기준 A는 별도 프로세스에 git show로 추출한 기준 모듈을 로드했으며 동작 중인 서버 코드를 되돌리지 않았다.

| 프레임워크 | 변경 전 | 변경 후 | 지표 |
| --- | ---: | ---: | --- |
| DeepEval | 7/17 | 17/17 | 대상/후보 ID의 exact custom metric |
| Ragas | 7/17 | 17/17 | 같은 실행 결과와 정답의 exact custom metric |

두 점수는 독립적인 서비스 품질 성공률이 아니며 의미 평가 모델은 호출하지 않았다. 사례 해시로 정답과 순서를 고정한다. 주차 조건 보존, 내부만 있는 코스, 복수 외부 식당, 명시 내부·번호·술집 지칭을 포함한다.

CI 연결은 `.github/workflows/evaluation-regression.yml`의 deterministic 및 후속 highlight-deterministic job이다. 실제 CI 명령과 결과:

```text
python -I .github/evaluation_ci.py offline-exec backend/llm/v2/tests/run_attachment_offline.py llm.tests.test_course_tonkatsu llm.tests.test_course_literal_edits llm.tests.test_course_audit_repairs.CourseSelectionRepairTest
# 27 tests OK

python -I .github/evaluation_ci.py offline-exec backend/llm/v2/evaluation/tonkatsu_contract.py export --output <artifact>/tonkatsu.json
# DeepEval 17/17

python -I .github/evaluation_ci.py offline-exec backend/llm/v2/evaluation/tonkatsu_contract.py score --input <artifact>/tonkatsu.json --output <artifact>/ragas.json
# Ragas 17/17
```

기존 launcher의 네트워크 차단과 분리된 평가 환경을 사용했다. CI 연결 검사 11개와 채점기 정상/오류 대조도 통과했다. 원격 GitHub CI 실행 결과를 뜻하지 않는다.

확대 회귀 **198개 중 196개 통과, 2개 실패**. 두 실패는 `test_course_signatures`의 칠리치즈 핫도그 수집 근거 기대값이며, 변경 전 모듈에서도 똑같이 실패했다. 테스트를 지우거나 메뉴 자료를 꾸며 통과시키지 않았다. 별도 정합성 점검 대상으로 남긴다.
