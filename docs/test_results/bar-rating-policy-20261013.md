# 술집 평점 필수 후보 정책 검증 — 2026-10-13

## 원인과 변경

`balanced` 일반 추천은 평점·실내 근거가 없는 외부 매장도 `qualityUnverified`로 통과시켰다. 이 예외가 술집에도 적용되어 평가가 확인되지 않은 매장이 코스에 포함될 수 있었다.

- 외부 술집은 모든 구장에서 실제 평점과 평가 수 1건 이상이 확인되어야 후보로 허용한다. `BAR`뿐 아니라 `FOOD`/`FOOD_OUT`/`FD6`로 전달되는 실제 술집 업종에도 적용한다.
- 식당·카페의 기존 일반 추천 정책과 자리어때 내부 먹거리의 평점 면제를 유지한다. 밤비·입술의 사용자 지정 제외, 유흥 업종과 확인된 실내 불량 제외도 유지한다.
- 다이닝코드 실제 프로필의 상호·주소 및 구조화 평점/본문 평점 일치를 확인한다. 카카오 후보나 모델이 전달한 임의 `rating` 필드는 근거로 인정하지 않는다.
- 평점 확인을 실내 승인과 별도 저장한다. 정적 승인 목록 외 신규 술집도 평점 확인 후 사용 가능하며, 실내 미확인을 실내 양호로 바꾸지 않는다. 기존 백그라운드 수집에서도 평점 근거를 따로 보존한다.
- 신규 평점 확인은 기존 페이지 수집기를 사용한다. 검색·사진 분석 모델을 추가하지 않으며 요청당 최대 6곳, 12초 조회 예산, 병렬 2개로 제한한다. 동일 후보 실패는 1시간 재조회를 보류한다. 반경과 앞 방문지 거리 제약은 유지하며 먼 캐시 후보가 가까운 신규 후보 확인을 막지 않는다.
- 휴무가 확인된 캐시 술집 때문에 다른 신규 후보 확인을 생략하지 않는다.

## 회귀 검사

성능 유지 지침의 필수 백엔드 검사 및 평점·수집·백그라운드 검사 총 208개 통과. 이후 휴무 후보 관련 검사 1개를 추가하고 관련 57개를 재실행해 모두 통과했다. 최초 방문 순서 테스트 2개는 가상 술집에 평점 근거가 없는 기존 격리 방식 때문에 실패했다. 방문 순서 테스트는 공통 후보 승인 경계를 명시적으로 대체하고, 실제 술집 승인·차단 동작은 별도 정책 검사에서 검증했다. 실제 수집 데이터를 변경하지 않았다.

주요 반례: 평점 누락/0/NaN, 평가 0건·잘못된 타입, 근거 URL 누락, 만료·미래 날짜, 다른 상호·지점·좌표, 가짜 평점 전달, 미확인 캐시, 사용자 지정 제외, 신규 1건 평가 통과, 실내 승인과 분리, 거리·반경, 동일 실패 재조회 방지, 조사 예산, 휴무 후보, 내부 먹거리 면제.

## 실제 실행

로컬 Docker의 실제 `/api/v2/chat/sessions/{id}/messages/`를 APIClient로 호출하여 완료 이벤트까지 측정했다. 프록시·브라우저 시간은 제외한다. 별도 검증용 대화만 생성했고 사용자 대화·지도는 수정하지 않았다. 운영 근거 캐시·프롬프트 캐시는 유지했으며 가상 경기 표시도 확인했다.
