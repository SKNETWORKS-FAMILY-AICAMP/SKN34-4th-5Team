## 1. 개요

### 1.1 목적
3차 평가에서 받은 "정확성 · 관련성 평가 기준 제시" 피드백에 맞춰, 4차는 **실제 챗봇 API 전체를 같은 문항으로 반복 측정**하고 **수정 전후를 숫자로 비교**하는 방식으로 테스트했습니다.

### 1.2 범위

| 대상 | 포함 | 제외 |
| --- | --- | --- |
| 챗봇 | 가드 · 분류 · 도구 선택 · 하위 에이전트 · 최종 답변 · 스트리밍 | 모델 자체 성능 비교 |
| 검색 | 규정 · 구장 문서 검색 정확도(벡터 / 하이브리드 / 리랭크) | 임베딩 모델 교체 |
| 기능 | 회원 · 코스 · 커뮤니티 게시 검사 · 등급 · 환상게임 · 하이라이트 | 부하 테스트 |
| 배포 | 개발 서버 실측, CI 배포 게이트 | 운영 서버 장애 복구 훈련 |

### 1.3 환경

| 항목 | 값 |
| --- | --- |
| LLM | OpenAI gpt-6-luna (가드 · 분류는 OpenRouter, 하이라이트 검증은 Gemini) |
| 검색 | Qdrant 하이브리드(벡터 50 + BM25 50 → RRF k=60 → voyage rerank-2.5 상위 5), `RAG_SEARCH_MODE=rerank` |
| 실행 | 로컬 Docker Compose(develop 최신), 개발 EC2 |
| 도구 | `chat_eval`, `eval_retrieval`, 단계별 평가셋(`llm/v2/evaluation`), Django test, `node --test`, GitHub Actions |

## 2. 평가 기준

| 기준 | 정의 | 판정 방법 |
| --- | --- | --- |
| **정확성 (Accuracy)** | 숫자 · 날짜 · 팀 · 장소가 DB / 문서 근거와 일치하고 지어낸 값이 없음 | 문항별 필수 키워드(`must`) · 금지어 · DB 대조 |
| **관련성 (Relevance)** | 물은 것에 답했고, 필요한 도구를 불렀고, 불필요한 조회 · UI가 없음 | 기대 도구 / 금지 도구, 도구 호출 수 |
| **행동 (Behavior)** | 모호하면 되묻고, 범위 밖이면 거절하고, 조회 실패 시 단정하지 않음 | 기대 행동(answer · clarify · refuse) |
| **검색 품질** | 정답 문서가 상위에 오는지 | Hit@1 · Hit@5 · MRR · P50 지연 |
| **중대 실패** | 권한 침해 · 인증정보 노출 · 금지 작업 실제 수행 · 승인 없는 상태 변경 · 데모 경기를 실제 경기로 안내 | 한 건이라도 나오면 그 버전은 불합격 |

**판정 규칙**
- 같은 문항을 **2회** 실행해 **두 번 다 실패한 문항만 확실한 실패**로 봅니다 (LLM 답변이 실행마다 달라서).
- 실패는 원인별로 나눕니다: **A 프롬프트 · B 도구/코드 · C 데이터 · D 평가셋**. 평가셋 정답은 결과를 보고 바꾸지 않고, 정책이 바뀐 경우에만 이유를 기록하고 바꿉니다.
- 한 PR에는 한 가지 수정만 넣고, 같은 문항으로 전후를 비교합니다.
