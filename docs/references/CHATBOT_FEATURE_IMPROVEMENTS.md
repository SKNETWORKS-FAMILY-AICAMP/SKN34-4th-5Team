# 챗봇 기능 개선 목록 — Open WebUI 비교 및 LLMOps

작성일: 2026-09-30

## 목적과 확인 범위

현재 직관 도우미 챗봇에서 빠진 일반적인 채팅 기능과 LLMOps용 사용자 피드백 수집 요구를 기록한다. **검토용 개선 목록이며 구현 승인 또는 완료 기록이 아니다.** 우선순위는 제안이며 세부 구현 범위는 별도 결정한다.

현재 워크스페이스의 소스와 Open WebUI 공식 문서를 비교했다. 미커밋 변경을 포함한 작성 당시 코드 기준이며, 배포 화면 실행·실제 모델 호출·운영 LangSmith 활성화 여부는 검증하지 않았다. 이후 코드 변경 시 상태를 다시 확인한다.

## 기능 개선 후보

| 기능 | 작성 당시 우리 챗봇 상태 | 제안 우선순위 / 목적 |
| --- | --- | --- |
| 답변 좋아요·싫어요 | 답변 평가 UI 및 채팅 피드백 API 없음 | 높음 / 만족도·실패 사례 수집 |
| 싫어요 사유·수정 의견 | 없음 | 높음 / 틀린 정보, 질문과 무관, 오래된 정보, 부적절한 코스 등을 구분 |
| 답변 복사 | 전체 답변·코드 블록 복사 버튼 없음 | 높음 / 기본 사용 편의 |
| 정상 답변 재생성 | 실패 재시도는 있지만 정상 답변 재생성 버튼 없음 | 높음 / 대안 답변 요청 |
| 이전 답변 보존·대화 분기 | 질문 수정 시 이후 대화를 현재 이력에서 제거하며 이전 버전 선택 UI 없음 | 중간 / 원본·수정 결과 비교 및 선호 데이터 수집 |
| 풍부한 Markdown 표시 | 제목·목록·굵게·간단한 코드 블록 지원. 표·클릭 가능한 Markdown 링크·인용문 등 미지원 | 높음 / 일정·구장 비교와 공식 출처 확인 |
| 대화 검색 | 최근 대화 목록은 있으나 제목·내용 검색 UI 없음 | 중간 / 지난 추천·설명 찾기 |
| 대화 제목 직접 변경 | 현재 화면에 변경 기능 없음 | 중간 / 대화 관리 |
| 대화 고정·폴더·태그 | 현재 화면에 없음 | 낮음 / 많은 대화 정리 |
| 채팅 내보내기·공유 | 채팅 다운로드·공유 UI 없음. 코스 공유와는 별개 | 중간 / 계획 전달·기록 보관 |
| 답변별 후속 질문 추천 | 시작 화면의 고정 추천 질문만 있음 | 중간 / 대화 이어가기 |
| 파일·이미지 첨부 | 채팅 입력창에 없음 | 후순위 / 티켓·좌석표·안내 이미지 질문 |
| 음성 입력·답변 읽기 | 채팅 화면에 없음 | 후순위 / 모바일 이용 편의 |
| 생성 중 다음 질문 작성·대기열 | 답변 생성 중 입력창 비활성화 | 낮음 / 연속 질문 편의 |

특히 우리 서비스에서는 경기 일정·구장 비교를 위한 **표 표시**, 공식 안내를 확인할 수 있는 **안전한 링크 표시**가 중요하다. Open WebUI 전체 기능을 그대로 이식하는 것이 목표는 아니다.

## 이미 구현되어 있어 재사용할 기능

- 새 대화, 최근 대화 선택, 대화 삭제
- 질문 수정 및 해당 질문부터 이후 대화 삭제
- 스트리밍 답변과 중단 버튼
- 오류 발생 시 다시 시도
- 도구·서브에이전트 진행 상황 표시
- 전체 채팅·팝업 채팅
- 추천 코스 카드 및 코스 작성 화면 연결

실패 재시도와 정상 답변 재생성은 별도 기능이다. 질문 수정 후 현재 이력에서 제거되는 것과 과거 checkpoint의 물리적 삭제도 동일한 의미가 아니다.

## LLMOps 피드백 수집 요구 후보

좋아요·싫어요 버튼만으로 강화학습 데이터가 완성되지는 않는다. 우선 평가·개선에 활용할 수 있도록 다음 기록의 연결이 필요하다.

| 기록 | 목적 |
| --- | --- |
| 평가 대상 답변 ID, 당시 질문·답변 스냅샷 | 수정·삭제 이후에도 평가 대상 식별 |
| 좋아요·싫어요, 사유, 선택적 의견 | 낮은 평가의 원인 구분 |
| 실행/Trace ID, 모델·프롬프트 버전 | 문제가 발생한 실행·설정 추적 |
| 사용한 검색 근거·도구 결과와의 연결 | 검색 문제와 생성 문제 구분 |
| 응답 시간·토큰·비용·실패 여부 | 품질 및 운영 성능 평가 |
| 개인정보 처리·학습 활용 동의/정책 | 대화의 학습 재사용 경계 설정 |

현재 코드에는 LangSmith 추적 코드와 골든셋 평가 명령이 존재한다. LLMOps가 전혀 없는 상태가 아니라, 확인한 범위에서 **사용자 평가를 답변·실행 기록에 연결하는 경로가 빠진 상태**다. 운영 활성화와 평가 실행 결과는 미확인이다.

- 좋아요·싫어요: 단일 답변의 만족도 신호
- 동일 질문의 답변 A/B 중 선택: 답변 간 선호 신호

DPO 등 선호학습을 고려하면 후자의 선호 쌍 구성·검수가 별도로 필요하다. 사용자 평가를 자동으로 정답으로 취급하거나 운영 모델의 자동 학습으로 연결하지 않는다.

구현 전 결정할 사항: 회원·비회원 평가 정책, 평가 변경·취소와 중복 처리, 원본 대화 삭제 시 피드백/스냅샷의 보존·삭제 정책, 관리자 조회 권한, 보관 기간과 개인정보 최소화. 기존 도구 결과나 내부 프롬프트를 일반 사용자에게 새로 노출하지 않는다.

## 제안 착수 순서

1. 답변 복사 + 좋아요·싫어요 + 싫어요 사유
2. 피드백을 답변 스냅샷·실행 ID에 연결
3. 표·안전한 링크를 지원하는 Markdown 표시 개선
4. 원래 답변을 보존하는 답변 재생성
5. 대화 검색·제목 변경·공유

최소 출발점은 전체·팝업 채팅의 답변 아래에 `복사 / 좋아요 / 싫어요 / 다시 생성` 액션을 제공하고 기존 추적·평가 체계에 연결하는 것이다. 이 순서는 제안이며 아직 구현하지 않았다.
