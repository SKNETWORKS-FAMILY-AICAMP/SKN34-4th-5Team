# 비회원 채팅 누적 이용 제한

- 메인 검색 영역과 AI 아이콘은 비회원도 채팅 화면으로 이동합니다.
- 비회원 질문은 기존 IP 기반 시간 구간 제한을 통과한 뒤 IP별 누적 2회 제한을 추가 검사합니다.
- 누적 횟수는 GuestChatUsage 테이블에 기록하며 새 대화, 새로고침, 캐시 삭제, 서버 재시작으로 초기화되지 않습니다.
- 입력 검증 실패와 기존 요청 빈도 제한(429)은 누적 횟수를 소비하지 않습니다.
- 서버가 접수한 질문은 모델 오류, 연결 종료, 사용자의 생성 중단 여부와 관계없이 1회로 계산합니다.
- 누적 한도 초과는 403 및 guest_quota_exhausted 코드를 반환하며 모델을 호출하지 않습니다.
- 회원 요청은 비회원 누적 한도를 차감하지 않습니다. 회원 API의 기존 인증 정책은 유지합니다.
- IP는 기존 신뢰 프록시 설정으로 추출하며 원문 대신 SECRET_KEY 기반 HMAC을 저장합니다. SECRET_KEY 변경 시 식별 키도 바뀌므로 운영 중 키 교체 시 별도 이관 정책이 필요합니다.
- 같은 공인 IP를 쓰는 사람들은 한도를 공유합니다. IP 변경을 동일인으로 식별하거나 차단하는 기능은 아닙니다.
- GET /api/v1/chat/guest/는 남은 횟수를 조회하며 소모하지 않습니다. POST는 기존 SSE 응답을 유지합니다.
- 배포 시 python manage.py migrate 실행이 필요합니다.

검증: llm.test_guest_quota는 실제 테스트 DB에서 누적·동시 요청·회원 예외·프록시 헤더 및 기존 요청 제한을 검증합니다. 모델은 모킹하므로 외부 LLM 비용이 발생하지 않습니다.
